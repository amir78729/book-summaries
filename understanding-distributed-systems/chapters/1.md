# Communication

## 1. The Network Stack & Leaky Abstractions
* **Network Layers:** Inter-process communication (IPC) moves down and up the network stack:
  * **Link Layer:** Operates on local networks (Ethernet, Wi-Fi) using MAC addresses.
  * **Internet Layer:** Routes packets across networks via the **Internet Protocol (IP)** on a best-effort basis.
  * **Transport Layer:** Connects processes using port numbers (e.g., **TCP**, **UDP**).
  * **Application Layer:** High-level application protocols (e.g., **HTTP**, **DNS**, **gRPC**).
* **Day-to-Day Takeaway:** Abstractions leak. High-level application code ultimately depends on socket state, packet loss, and network round-trip times (RTT).

## 2. Reliable Links (TCP vs. UDP)
* **TCP Mechanisms:** Provides a reliable byte-stream over unreliable IP by splitting data into sequentially numbered **segments**, acknowledging delivered packets (**ACKs**), retransmitting on timeouts, and verifying integrity via **checksums**.
* **Connection Lifecycle & Connection Pools:**
  * Establishes connections using a **three-way handshake** (SYN \\(\rightarrow\\) SYN/ACK \\(\rightarrow\\) ACK), introducing a full RTT latency penalty before data transmission begins.
  * Rapidly opening and closing connections causes sockets to accumulate in the **`TIME_WAIT`** state, leading to **socket exhaustion**. 
  * **Day-to-Day / Interview Application:** Always use **connection pools** to reuse existing TCP connections and avoid recurring handshake latencies and socket starvation.
* **Flow & Congestion Control:**
  * **Flow Control:** Prevents the sender from overwhelming the receiver using a **receive buffer** window.
  * **Congestion Control:** Prevents overwhelming the network by adjusting a **congestion window** (`WinSize`). Max bandwidth is constrained by latency: \\(\text{Bandwidth} = \frac{\text{WinSize}}{\text{RTT}}\\).
* **UDP & Custom Protocols:** UDP is a lightweight, connectionless protocol with no sequencing, ACKs, or flow/congestion control. It excels in real-time, loss-tolerant applications (e.g., gaming, media streaming) or for bootstrapping custom protocols like **QUIC / HTTP/3**.

## 3. Secure Links (TLS)
* **Core Guarantees:** **Transport Layer Security (TLS)** provides **encryption** (privacy), **authentication** (digital certificates), and **integrity** (tamper protection) on top of TCP.
* **Hybrid Encryption:** Uses slow **asymmetric encryption** (public/private keys) during the initial handshake to securely negotiate a shared secret, then switches to fast **symmetric encryption** for application data payload transfer.
* **Latency & Reuse:** Modern handshakes cost 1–2 RTTs. Reusing existing TLS connections minimizes CPU overhead and latency.

## 4. Discovery (DNS)
* **Hierarchical Resolution:** The **Domain Name System (DNS)** is a distributed, hierarchical, and eventually consistent key-value store mapping domain names to IP addresses.
* **Resolution Process:** Resolvers query root name servers, TLD servers, and authoritative name servers iteratively, heavily relying on **TTL-based caching** at every level to maintain speed.
* **Day-to-Day / Interview Application:** Cache stale DNS entries or short TTLs during active deployments to allow quick traffic rerouting without unexpected propagation delays.

## 5. APIs, Serialization, & Protocols
* **Communication Styles:** **Direct** (request-response over HTTP/RPC requiring both client/server online simultaneously) vs. **Indirect** (asynchronous messaging brokers like Kafka).
* **Serialization Trade-Offs:**
  * **Textual (JSON):** Human-readable and self-describing, but verbose and slower to parse.
  * **Binary (Protocol Buffers):** Compact, highly performant, and type-safe via schemas, but requires tooling to inspect.
* **Protocol Evolution:**
  * **HTTP/1.1:** Textual protocol suffering from **head-of-line (HOL) blocking** (requests on a single connection must be processed sequentially).
  * **HTTP/2:** Binary protocol enabling **multiplexing** of multiple requests/responses over a single TCP connection.
  * **HTTP/3:** Built on **UDP (QUIC)** to eliminate TCP-level HOL blocking across streams.
* **API Frameworks:** **gRPC** is ideal for high-performance internal microservice communication, while **RESTful HTTP APIs** are standard for client-facing public endpoints.

## 6. Idempotency & Safe Retries
* **The Timeout Problem:** When a network call times out, the client cannot know if the server failed before receiving the request, failed during execution, or processed it and crashed before returning the response.
* **Method Guarantees:** `GET`, `PUT`, and `DELETE` are inherently **idempotent** (executing them multiple times produces the same end state). `POST` is non-idempotent.
* **Idempotency Keys:**
  * To make non-idempotent operations (like payment processing or creation via `POST`) retry-safe, clients attach a unique **Idempotency Key** (UUID) in the request header.
  * The server processes the request and persists the key alongside the result atomically within a **database transaction**.
  * Duplicate retries with the same key bypass re-execution and safely return the previously saved response.
